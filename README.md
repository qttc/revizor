# revizor

Локальный редактор правок для работы с агентом. Агент открывает документ в Chrome. Владелец выделяет фрагмент и пишет свою версию или комментарий, оставляет комментарий к слайду, графику или таблице и пишет общие комментарии. Правки сразу ложатся в файл рядом с документом. По слову «поправь» агент применяет их и помечает применёнными.

Подходит для текстов (`.md`, `.txt`), HTML-отчётов и деков, в том числе со слайдами во фреймах и самораспаковывающихся бандлов. Зависимостей нет: Python 3.9+ из коробки macOS и Chrome.

## Как это выглядит

1. В сессии Claude Code: `/revizor reports/market-2026-10-19.html` или «открой в редакторе».
2. Агент запускает сервер в фоне, открывает вкладку и пишет, куда идут правки: `reports/market-2026-10-19.review.json`.
3. Ты правишь в браузере. Каждое изменение сохраняется сразу, вкладку можно закрыть в любой момент.
4. Пишешь в тот же чат «поправь». Агент берёт файл правок, применяет их к документу, помечает применёнными и отчитывается: сколько применено, что отклонено и почему.
5. Второй круг – в той же вкладке: обновить, дописать, снова «поправь». Агент получит только новые правки.

Кнопка «Готово» в редакторе необязательна. Она закрывает сервер и отдаёт агенту сводку. Документ после неё агент не трогает, пока владелец не скажет.

## Установка

```
git clone git@github.com:qttc/revizor.git ~/Personal/revizor
~/Personal/revizor/install.sh
```

`install.sh` кладёт симлинк `~/.claude/skills/revizor` → `skill/`, и скилл становится виден в любом пространстве. Повторный запуск безопасен. Ссылку `~/.claude/skills/review` от версии до переименования скрипт снимает сам.

## Команды

```
python3 revizor.py open FILE [--port N] [--no-browser]   # сервер в фоне до «Готово», затем сводка в stdout
python3 revizor.py show FILE [--json]                     # правки, которые ждут агента
python3 revizor.py mark FILE ID... --state applied|rejected [--note TEXT]
python3 revizor.py --version
```

`open` пишет в stderr ссылку на редактор и путь к файлу правок. Агент запускает её в фоне и получает уведомление, когда команда завершилась.

## Редактор

- Выделить текст → «Изменить» (`E`) или «Комментарий» (`C`). В карточке справа – «было», поле «стало» с исходным текстом и необязательное «почему».
- «+ К блоку» → клик по графику, таблице, абзацу или слайду. Агент получит раздел, CSS-путь и название блока.
- «+ Общий» – комментарий ко всему документу.
- Регистр в шапке (отчёт, дек, Slack, спека, док, письмо, клиентская копия) попадает в стилевые пары.
- Клик по подсветке открывает карточку, клик по цитате в карточке прокручивает к месту.
- Панель сворачивается кнопкой `⇥`. Пока она открыта, широкий контент (дек 1280 px) ужимается до свободной ширины.
- «Готово» – только кликом и с подтверждением. Горячей клавиши нет: действие закрывает редактор.

## Что поддерживается

| Документ | Как открывается |
|---|---|
| `.md`, `.markdown`, `.txt` | Сервер оборачивает текст в страницу байт в байт, правка ищется по смещению в файле |
| `.html`, `.htm` | Отдаётся как есть, слой правок встраивается перед последним `</body>`. Картинки и стили по относительным путям берутся из папки документа |
| Слайды во фреймах того же origin | Каждый фрейм правится как страница. У правки есть поле `frame` – заголовок фрейма |
| Самораспаковывающийся бандл (`__bundler/manifest`) | Работает, если страница подменяет `<html>` и строит слайды скриптом после загрузки. Текст слайдов в таком файле сжат, поэтому сводка просит агента править исходник дека |

## Формат `*.review.json`

Файл лежит рядом с документом: `report.md` → `report.review.json`. Он и есть вся история: что ждёт агента, что применено, что отклонено и почему.

```json
{
  "version": 1,
  "doc": "report.md",
  "doc_sha": "9f2c…",
  "register": "report",
  "status": "open | done",
  "created": "2026-10-21T14:02:11+03:00",
  "updated": "2026-10-21T14:20:40+03:00",
  "items": [
    {
      "id": "rmgx3k1a9f",
      "kind": "edit",
      "scope": "text",
      "start": 120, "end": 164,
      "quote": "исходный фрагмент",
      "prefix": "до 32 символов перед",
      "suffix": "до 32 символов после",
      "where": "Цифры",
      "replacement": "как написал владелец",
      "why": "необязательно",
      "state": "pending | applied | rejected",
      "note": "почему отклонено, если отклонено",
      "created": "…", "resolved": "…"
    },
    { "id": "…", "kind": "comment", "scope": "text", "quote": "…", "prefix": "…", "suffix": "…", "comment": "что поправить", "state": "pending" },
    { "id": "…", "kind": "comment", "scope": "block", "frame": "03 · Цифры", "selector": "#chart > div:nth-of-type(1)", "snippet": "график: Выручка по неделям", "text": "начало текста блока", "where": "03 · Цифры", "comment": "добавь источник", "state": "pending" },
    { "id": "…", "kind": "comment", "scope": "doc", "comment": "общий комментарий", "state": "pending" }
  ]
}
```

- `scope`: `text` – фрагмент, `block` – элемент страницы, `doc` – весь документ.
- `where` – слайд, раздел или ближайший заголовок над правкой.
- `frame` – заголовок фрейма слайда, если правка внутри него. `start`, `end` и `selector` тогда считаются внутри фрейма.
- `start`/`end` – смещения в видимом тексте страницы на момент правки, для `.md` они совпадают с файлом. Документ мог поменяться, поэтому место ищется по `quote` с `prefix` и `suffix`. Не нашлось – `orphan: true`.
- `register`: `report`, `deck`, `slack`, `spec`, `doc`, `email`, `client`, `other` или `null`.
- Стилевая пара – это `kind: "edit"`: `quote` → `replacement`, плюс `why` и `register`. Комментарии в пары не идут.

## Как устроено

- `revizor.py` – сервер на `http.server` и CLI. Слушает только `127.0.0.1` и раздаёт только папку документа. Файлы правок `*.review.json` закрыты даже внутри неё. Запись в файл правок атомарная: через временный файл и `replace`.
- `web/overlay.js` – слой правок, один файл без сборки. Панель живёт в shadow DOM, стили страницы её не задевают. Подсветка – CSS Custom Highlight API (Chrome 105+), DOM документа не меняется. За заменой `<html>` и за догрузкой текста в слайдах следит `MutationObserver`.
- Страница присылает только живые правки. Применённые и отклонённые хранит файл, и открытая вкладка их не воскрешает: агент может закрывать правки, пока редактор открыт.
- `skill/SKILL.md` – скилл для Claude Code: как запустить, когда применять, как помечать.

## Ограничения

- Только Chrome и браузеры на Chromium: без Highlight API правки сохраняются, подсветки нет.
- Фреймы с другого origin недоступны, правки в них не ставятся.
- Абсолютные пути к ресурсам (`/assets/…`) в HTML не подтянутся: сервер раздаёт папку документа от `/doc/`.
- Агент применяет правку к исходнику. В HTML между словами цитаты могут стоять теги и сущности, поэтому агент меняет только текст. Бандл агент не правит: текст слайдов сжат, править нужно исходник.

## Разработка

```
python3 -m unittest discover tests
```

Тесты покрывают сервер, отдачу HTML со слоем, защиту папки, слияние правок со страницы и CLI. Слой правок проверяется вручную в Chrome: выделение, «+ К блоку», перезагрузка с поиском места, фреймы. Изменения – в [CHANGELOG.md](CHANGELOG.md), правила для агента в этом репо – в [CLAUDE.md](CLAUDE.md).

## Связь с personal-graph

Файлы правок остаются в пространстве документа. Хаб `~/Personal` их только читает: `/graph-sync` находит `*.review.json` по пространствам и забирает пары «было → стало» в `writing-style`.
