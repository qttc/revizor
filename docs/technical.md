# Ревизор: техническое описание

Для тех, кто правит сам Ревизор или пишет агента, который с ним работает. Что это и зачем – в [README](../README.md).

## Команды

```
python3 revizor.py open FILE [--port N] [--no-browser]   # сервер в фоне до «Завершить ревью», затем сводка в stdout
python3 revizor.py wait FILE [--interval S]              # ждать работу из редактора: проверку на нейрослоп и правки Live Edit
python3 revizor.py suggest FILE FINDINGS.json            # записать находки смысловой проверки (- – из stdin)
python3 revizor.py update [--check]                      # обновиться из репо и показать, что поменялось
python3 revizor.py style [init [--name N] [--force]]     # какой скилл стиля найден; init – создать из шаблона
python3 revizor.py pairs [--count] [--ack] [--dir D]     # новые пары для обучения скилла стиля (JSON); --ack – порция разобрана
python3 revizor.py show FILE [--json]                     # правки, которые ждут агента
python3 revizor.py mark FILE ID... --state applied|rejected [--note TEXT]
python3 revizor.py --version
```

`open` пишет в stderr ссылку на редактор и путь к файлу правок. Агент запускает её в фоне и получает уведомление, когда команда завершилась. Сценарий для агента – [skill/SKILL.md](../skill/SKILL.md).

`install.sh` кладёт симлинк `~/.claude/skills/revizor` → `skill/`. Повторный запуск безопасен, ссылку `~/.claude/skills/review` от версии 0.1 до переименования он снимает сам.

## Редактор

- Выделить текст → «Изменить» (`E`) или «Комментарий» (`C`). В карточке – «было», поле «стало» с исходным текстом и необязательное «почему». Цитата перелетает от выделения в новую карточку.
- «Выбрать блок» → клик по графику, таблице, абзацу или фрейму слайда. `Esc` – отмена.
- «Общий комментарий» – комментарий ко всему документу.
- Markdown открывается в двух видах, переключатель «Оформление / Текст» сверху, выбор хранится в файле правок. В «Оформлении» ссылки открываются по ⌘-клику, «Выбрать блок» берёт абзац, пункт, таблицу, код или раздел целиком (клик по заголовку). В поле «стало» `⌘B` и `⌘I` оборачивают выделение в `**` и `_`, под полем превью, в карточке пословный дифф «было → стало».
- Формат текста определяется сам, в списке это «Авто · Отчёт»: дек – три фрейма или слайда и больше, отчёт – графики и таблицы в HTML или пять чисел с единицами в тексте, спека – разделы «Требования», «Критерии» и подобные, письмо – обращение и подпись, Slack – короткий текст без заголовков, клиентская копия – английский HTML. Ручной выбор главнее, пункт «Авто» возвращает автоопределение.
- Клик по подсветке открывает карточку, клик по цитате в карточке прокручивает к месту.
- При прокрутке списка правок шапка сжимается до строки с названием, файлом и форматом и раскрывается у начала списка или по клику на название. Сжимается, только если список длиннее 140 px сверх видимой части, иначе шапка дёргалась бы на границе.
- Панель сворачивается в пилюлю «Ревизор · N». Пока панель открыта, широкий контент (дек 1280 px) ужимается до свободной ширины. Уже 760 px панель встаёт снизу на половину экрана.
- Тон стекла берётся по яркости фона страницы, тема системы решает, только если фон прозрачный.
- «Завершить ревью» – только кликом и с подтверждением. Горячей клавиши нет: действие закрывает редактор.
- Live Edit (бета) – переключатель в шапке, подробности в разделе ниже.
- Проверка на нейрослоп идёт сама при открытии, подробности в разделе ниже.
- Сохранение не прошло – статус красный и кнопка «Повторить».

## Что поддерживается

| Документ | Как открывается |
|---|---|
| `.md`, `.markdown` | Два вида. «Текст» – исходник байт в байт. «Оформление» строит слой из дерева mdast (CommonMark + GFM: таблицы, задачи, зачёркивание, сноски), сырой HTML показывается текстом. Картинки по относительным путям – из папки документа |
| `.txt` | Текст байт в байт, один вид |
| `.html`, `.htm` | Отдаётся как есть, слой правок встраивается перед последним `</body>`. Картинки и стили по относительным путям берутся из папки документа |
| Слайды во фреймах того же origin | Каждый фрейм правится как страница. У правки есть поле `frame` – заголовок фрейма |
| Самораспаковывающийся бандл (`__bundler/manifest`) | Слой переживает подмену `<html>` и слайды, которые строятся скриптом после загрузки. Текст слайдов в файле сжат, поэтому сводка просит агента править исходник дека |

## Формат `*.review.json`

Файл лежит рядом с документом: `report.md` → `report.review.json`. Если в папке есть документ с тем же именем и другим расширением, у каждого полное имя: `report.md.review.json`, `report.html.review.json`. Файл с коротким именем остаётся у документа из своего поля `doc`. Это вся история: что ждёт агента, что применено, что отклонено и почему.

```json
{
  "version": 1,
  "doc": "report.md",
  "doc_sha": "9f2c…",
  "register": "report",
  "register_auto": true,
  "status": "open | done | stopped",
  "created": "2026-10-21T14:02:11+03:00",
  "updated": "2026-10-21T14:20:40+03:00",
  "items": [
    {
      "id": "rmgx3k1a9f",
      "kind": "edit",
      "scope": "text",
      "start": 120, "end": 164,
      "quote": "исходный фрагмент",
      "prefix": "до 32 символов перед",
      "suffix": "до 32 символов после",
      "where": "Цифры",
      "replacement": "как написал владелец",
      "why": "необязательно",
      "state": "pending | applied | rejected",
      "note": "почему отклонено, если отклонено",
      "created": "…", "resolved": "…"
    },
    { "id": "…", "kind": "comment", "scope": "text", "quote": "…", "prefix": "…", "suffix": "…", "comment": "что поправить", "state": "pending" },
    { "id": "…", "kind": "comment", "scope": "block", "frame": "03 · Цифры", "selector": "#chart > div:nth-of-type(1)", "snippet": "график: Выручка по неделям", "text": "начало текста блока", "where": "03 · Цифры", "comment": "добавь источник", "state": "pending" },
    { "id": "…", "kind": "comment", "scope": "doc", "comment": "общий комментарий", "state": "pending" }
  ]
}
```

Схема – [review.schema.json](review.schema.json). Обязательны `version`, `doc`, `status`, `items`, у правки – `id` и `kind`. Нет `state` – правка ждёт агента.

- `status`: `open` – редактор открыт, `done` – нажато «Завершить ревью», `stopped` – сервер остановили без него.
- `scope`: `text` – фрагмент, `block` – элемент страницы, `doc` – весь документ.
- `where` – слайд, раздел или ближайший заголовок над правкой.
- `frame` – заголовок фрейма слайда, если правка внутри него. `start`, `end` и `selector` тогда считаются внутри фрейма.
- `start`/`end` – смещения на момент правки. Для `.md` и `.txt` это смещения в файле в обоих видах, для HTML – в видимом тексте. Документ мог поменяться, поэтому место ищется по `quote` с `prefix` и `suffix`. Не нашлось – `orphan: true`.
- `lines` – у блока в Markdown: строки исходника `[с, по]`. Раздел по заголовку – до следующего заголовка того же уровня или выше.
- `view` – вид Markdown, `md` или `plain`. Нужен самому редактору: порт каждый раз новый, и localStorage вид не удержит.
- `dismissed` – находки проверки, которые владелец отметил «это не нейрослоп»: `rule`, `quote`, `prefix` (16 символов перед находкой). У правки из проверки есть `rule` (id правил через запятую) и `source: "radar"`.
- `scan` – смысловая проверка: `state` (`requested`, `taken`, `done`), время запроса и `sha` текста, по которому её просили. `findings` – находки агента: `quote`, `start`, `end`, `prefix`, `suffix`, `rule`, `title`, `why`, `rewrite` (`""` – удалить, `null` – варианта нет), `frame` у слайда.
- `live` – включён ли Live Edit. У правки в Live Edit: `sent` – когда владелец отправил её агенту, `taken` – когда её забрал `wait`.
- `register`: `report`, `deck`, `slack`, `spec`, `doc`, `email`, `client`, `other` или `null`. `register_auto` – формат определил Ревизор, владелец его не менял. В файлах 0.1 поля нет, заданный там формат считается ручным.
- Стилевая пара – это `kind: "edit"`: `quote` → `replacement`, плюс `why` и `register`. Комментарии в пары не идут.

## Совместимость

С 1.0.0 версии идут по SemVer. Ломающее изменение того, что ниже, – только в мажорной версии, с миграцией в CHANGELOG.

Стабильно:
- команды и флаги CLI, коды выхода: 0 – успех, 1 – ошибка ввода (нет файла, неизвестный id), 2 – файл правок не читается или платформа не поддерживается, 3 – `pairs` вызван не из папки `learn_from`, 130 – `open` остановлен по Ctrl-C;
- `show --json` и JSON на выходе `pairs`;
- формат `*.review.json` версии 1 по [схеме](review.schema.json). Новые необязательные поля могут появляться в минорных версиях, читатель их пропускает;
- манифест скилла `revizor.json`, правила `revizor-rules.json`, журнал `revizor-learned.json`;
- ключи `~/.config/revizor/config.json` (`style_skill`, `learn_from`) и переменные `REVIZOR_STYLE_SKILL`, `REVIZOR_NO_UPDATE_CHECK`.

Внутреннее, меняется без предупреждения:
- текстовые сводки `open`, `wait`, `show` без `--json`. Их читает агент по скиллу, скилл обновляется вместе с ними;
- HTTP `/api/*` между сервером и слоем правок;
- файлы в `~/.cache/revizor`.

## Устройство

- `revizor.py` – сервер на `http.server` и CLI. Слушает только `127.0.0.1` и раздаёт только папку документа, без скрытых файлов и папок. Файлы правок `*.review.json` закрыты даже внутри неё, без учёта регистра. Запросы с чужим Host отклоняются (DNS-rebinding), POST – только `application/json` со своим Origin. Тело до 10 МБ. Запись в файл правок атомарная: через временный файл и `replace`.
- `web/shell.css`, `web/markdown.css` – страница для `.md` и `.txt`, сервер вставляет их в `<style>`. `lang` страницы – по языку документа.
- `web/overlay.js` – слой правок, один файл без сборки. Панель живёт в shadow DOM, стили страницы её не задевают. Подсветка – CSS Custom Highlight API (Chrome 105+), DOM документа не меняется. За подменой `<html>` и догрузкой текста в слайдах следит `MutationObserver`.
- `web/vendor/` – Motion 11.11.17 (MIT), Playfair Display, кириллица и латиница (OFL), и парсер Markdown. Сервер отдаёт Motion вместе со слоем в обёртке: AMD и CommonJS страницы он не видит, её `window.Motion` не трогает, слою достаётся как `window.__revizorMotion`. Без Motion анимации идут через Web Animations API. При `prefers-reduced-motion` остаются только прозрачность и цвет.
- Шрифт объявляется в документе: `@font-face` внутри shadow DOM Chrome не подхватывает.
- Markdown: `web/vendor/mdast-gfm.js` – `mdast-util-from-markdown@2.0.2` с `micromark-extension-gfm@3.0.0` и `mdast-util-gfm@3.0.0`, собран esbuild, 49 пакетов под MIT (`web/vendor/LICENSE-mdast.md`). Сервер добавляет его в бандл слоя только для Markdown. Каждый текстовый узел оформленного вида помнит смещение в исходнике. Экранирование (`\*`) и сущности (`&amp;`) режут значение на куски, совпадающие с исходником, поэтому правка через них уходит в файл точно: на экране `&`, в правке `&amp;`.
- Пересборка парсера: `tools/vendor-md/build.sh`, нужны node и npm. Версии – в `tools/vendor-md/package.json`.
- Страница присылает только живые правки. Применённые и отклонённые хранит файл, и открытая вкладка их не воскрешает: агент может закрывать правки, пока редактор открыт.
- Повторный `open` того же документа встаёт на прошлый порт (`~/.cache/revizor/ports.json`, ключ – хэш пути), если он свободен. После «Завершить ревью» страница раз в 1,5 с опрашивает `/api/state` и перезагружается, когда сервер снова отвечает со `status: open`. Если ревью закончилось «Завершить ревью», `open` ждёт запрос от старой вкладки 4 с и только потом открывает новую.
- Файл правок пишут три процесса: сервер, `mark` и `wait`. Каждое чтение-изменение-запись идёт под `flock`, лок лежит в `~/.cache/revizor/locks/`, рядом с документом ничего лишнего не появляется.

## Проверка на нейрослоп

При открытии слой прогоняет по тексту каждого корня (страница, фреймы) регулярки и подчёркивает находки волной (`::highlight(rv-slop)`). Находки не хранятся, они пересчитываются по тексту. В файл попадает только то, что владелец взял в правку или отклонил.

- Не проверяются код (в Markdown – блоки и `инлайн`, в HTML – `code`, `pre`, `kbd`, кнопки, `nav`), ссылки и короткие цитаты в «ёлочках» до 24 символов: это названный оборот, а не речь. Правила с `"lang": "ru"` срабатывают только в строке с кириллицей.
- Находки одного предложения – одна строка в панели. «Исправить» есть, когда у всех правил строки есть автоисправление (`fix`). «Переписать» создаёт правку на всё предложение, автоисправления в «стало» уже применены, курсор в поле. «Агенту» создаёт комментарий с названием и объяснением приёма. В HTML предложение не выходит за свой блок.
- Правила: базовые в `rules/ru.json` плюс `revizor-rules.json` скилла стиля. Формат правила: `id`, `title`, `why`, `pattern` и `flags` (регулярка JavaScript, юникод через `u`), `lang` (`ru` или `any`), необязательный `fix` – пара `[регулярка, замена]` для автоисправления. Правило скилла с тем же `id` заменяет базовое, `{"id": "...", "off": true}` выключает его.

### Смысловой проход агентом

Регулярки не видят морали под блоком, разнесённую антитезу, хиазм, триплеты и ровный ритм. Это делает агент.

1. При открытии страница отправляет на `/api/scan` текст каждого корня – тот же, по которому считаются смещения правок. Сервер кладёт его в `~/.cache/revizor/text/` и ставит `scan.state: requested`. Повторно проверка не запрашивается, пока `sha` документа совпадает с `scan.sha`. Текст поменялся – в группе появляется «Текст поменялся – проверить заново».
2. `wait` отдаёт запрос раньше правок Live Edit: печатает путь к тексту, язык текста, каталог примет под этот язык (`references/*tells-<язык>*.md` скилла стиля или `rules/semantic-ru.md`), регистр и id правил, которые уже ловят регулярки.
3. Агент пишет находки JSON-списком и вызывает `suggest`. Команда ищет каждую цитату в тексте своего корня, сохраняет позицию с контекстом и ставит `scan.state: done`. Цитаты, которых нет в тексте, она перечисляет, агент их правит и вызывает `suggest` снова.
4. Пока проверка идёт, страница раз в 1,5 с спрашивает `/api/state`, в шапке группы – «агент читает…». Запрос висит дольше 90 с без агента – «смысловая проверка ждёт агента».

Находки агента идут в ту же группу, что и регулярки, и привязываются к тексту так же, как правки: по цитате и контексту. Строка с вариантом агента показывает «→ как станет» и кнопки «Принять» и «Поправить». У правки из такой строки `source: "radar-agent"`. Переписано почти целиком – карточка показывает «было» и «стало» целиком, без пословного диффа.

### Как находится скилл стиля

Настраивать ничего не нужно. Ревизор смотрит `~/.claude/skills/*` и берёт скилл с наибольшим счётом: `revizor.json` в корне – 100, каталог примет `references/*tells*.md` – 50, в начале `SKILL.md` есть «стиль», «голос», style, voice или writing – 20, `references/examples.md` – 10. Ниже 30 – скилла нет, работают базовые правила. Свой скилл Ревизора в кандидаты не идёт. Ошибся – путь задаётся переменной `REVIZOR_STYLE_SKILL` или полем `style_skill` в `~/.config/revizor/config.json`. Что найдено, показывает `revizor.py style` и подпись в панели.

Скилл ищется под язык документа: ru, если кириллицы больше латиницы, иначе en. `style_skill` может быть словарём `{"ru": "...", "en": "..."}`. Языка в нём нет – автопоиск, скиллы, заданные под другие языки, в него не идут. Переменная `REVIZOR_STYLE_SKILL` – один скилл на все языки.

## Обучение скилла стиля

Механику делает `revizor.py`, разбор по смыслу – агент по плейбуку [skill/learn.md](../skill/learn.md).

- **Откуда пары.** `open` записывает путь документа в `~/.cache/revizor/docs.json`. `pairs` читает файлы правок этих документов и папок из `--dir`. `--discover` добавляет поиск Spotlight по всему диску (`mdfind -name .review.json`), чтобы разово подхватить ревью до появления реестра. По умолчанию он выключен: на диске лежат и чужие файлы правок. `--count` только считает и порцию не трогает. Файлы правок только читаются.
- **Что идёт в порцию.** `pairs` – применённые правки, где «стало» отличается от «было» не только пробелами. `confirmed` – механика из проверки, принятая одним кликом: подтверждает правило, примером не становится. `dismissed` – отметки «это не нейрослоп». Применённые комментарии в пары не идут: это просьба, а не образец.
- **Журнал.** `revizor-learned.json` в скилле: `seen` – что уже разобрано (хэш от `путь файла правок#id`: пути к рабочим документам в скилл не попадают, журналы 0.8.0-dev с путями переводятся сами), `stats` – по каждому правилу `taken` и `dismissed`. `pairs` пишет порцию в `~/.cache/revizor/pairs-batch.json`, `pairs --ack` переносит её в журнал и обновляет статистику.
- **Файлы скилла.** Роли – в `revizor.json` скилла (`files`: `examples`, `catalog`, `voice`, `rules`, `ledger`), значение – путь на все языки или словарь `{"ru": "...", "en": "..."}`. Без манифеста – раскладка канона стиля: `references/examples.md`, `references/*tells-<язык>*.md` (нет – общий `*tells*.md` без языка, нет и его – `references/ai-tells-<язык>.md` создаст обучение), `references/voice.md`, `revizor-rules.json`, `revizor-learned.json`.
- **Языки.** Каждая запись порции несёт `lang` по своему тексту, `langs` – скилл, файлы и статистика под каждый язык. Журналов столько, сколько разных скиллов: `pairs` пропускает разобранное по всем, `--ack` пишет запись в журнал скилла её языка.
- **Порция.** Не больше 40 сигналов (`--max`), остальное приходит в следующий раз: первая порция после обновления бывает большой.
- **Где учить.** `learn_from` в `~/.config/revizor/config.json` – обучение только из этой папки и её подпапок, в остальных `pairs` отвечает, откуда его запустить, а `--count` возвращает 0. Нужно тем, у кого несколько изолированных рабочих пространств и скилл стиля общий. Нет настройки – обучение откуда угодно.
- **Нет скилла.** Сначала ищется слабый кандидат – `SKILL.md`, где в начале есть «стиль» или style, без каталога и примеров: обучение подключается к нему и создаёт недостающие файлы. Нет и такого – `pairs` создаёт скилл из `templates/style-skill/` в `~/.claude/skills/writing-style` (занято – `revizor-style`), каталог примет стартует с `rules/semantic-ru.md`. Дальше скилл находится сам: у него есть `revizor.json`.
- **Когда.** Скилл Ревизора после «Завершить ревью» вызывает `pairs --count` и учит при 5 и больше новых сигналах, по словам «обучи стиль» – всегда.

## Live Edit (бета)

Правки уходят агенту по одной, документ обновляется на странице, пока ревью идёт.

1. Владелец включает Live Edit. У каждой карточки появляется «Отправить агенту», у «Завершить ревью» – второстепенный вид.
2. «Отправить агенту» ставит правке `sent`. Карточка закрывается для правки и показывает «В очереди у агента», её можно отозвать.
3. Агент держит в фоне `revizor.py wait FILE`. Команда раз в секунду смотрит файл, забирает отправленные правки (ставит `taken`), печатает сводку и выходит. Агент применяет, отмечает `mark` и запускает `wait` снова.
4. Страница раз в 1,5 с спрашивает `/api/state`. Видит `taken` – карточка показывает «Агент применяет…», поля и удаление закрыты. Сервер тоже не даёт странице поменять или удалить такую правку. Правка закрыта – карточка уходит в историю, всплывает «Агент применил правку» или причина отказа.
5. Поменялся хэш документа – текст и Markdown берут новый текст с `/api/source` и перерисовываются на месте, HTML перезагружается с сохранением прокрутки. Пока владелец печатает в поле, перезагрузка HTML ждёт.

Правка в очереди дольше минуты – карточка подсказывает написать в чат «поправь»: цикл агента, видимо, не запущен. `wait` заканчивается сам, когда ревью завершено (`status: done`) или сервер остановлен (`stopped`). Забранные правки в сводку `open` при завершении не попадают: их агент доделывает в цикле.

## Ограничения

- Только Chrome и браузеры на Chromium: без Highlight API правки сохраняются, подсветки нет. На macOS открывается Chrome, без него и на Linux – браузер по умолчанию.
- macOS и Linux. Windows не поддерживается: блокировки файла правок сделаны на `fcntl`. Работает WSL.
- Фреймы с другого origin недоступны, правки в них не ставятся.
- Абсолютные пути к ресурсам (`/assets/…`) в HTML не подтянутся: сервер раздаёт папку документа от `/doc/`.
- Агент применяет правку к исходнику. В HTML между словами цитаты могут стоять теги и сущности, поэтому агент меняет только текст. Бандл агент не правит: текст слайдов сжат, править нужно исходник.

## Разработка

```
python3 -m unittest discover tests
```

Тесты покрывают сервер, страницу Markdown с двумя видами, номера строк в сводке, отдачу HTML со слоем, бандл слоя с Motion, шрифты и закрытую папку `vendor`, защиту папки документа, слияние правок со страницы и CLI. Слой правок проверяется вручную в Chrome на `tests/fixtures/markdown.md`, тексте, HTML-отчёте и деке со слайдами во фреймах, на 1440 и 390 px. Для Markdown – правки через жирное, ссылку, код, таблицу, экранирование и сущности: цитата в файле правок совпадает с исходником. Правила для агента в этом репо – [CLAUDE.md](../CLAUDE.md), изменения – [CHANGELOG.md](../CHANGELOG.md).

## Обновления

`open` раз в сутки сравнивает свою версию с последним тегом `vX.Y.Z` публичного репо (`git ls-remote`, таймаут 3 с, кэш – `~/.cache/revizor/update.json`). Наружу уходит только этот запрос, о документах и правках он ничего не передаёт. Версия новее – строка в stderr для агента и строка внизу панели. Без сети проверка молча пропускается, выключается `REVIZOR_NO_UPDATE_CHECK=1`.

`revizor.py update` – `git fetch --tags`, переход `--ff-only` на последний тег `vX.Y.Z` и `install.sh` в папке клона, потом разделы CHANGELOG между старой и новой версией. Ревизор поставлен не через git или в папке есть свои изменения – команда останавливается и объясняет почему. `update --check` только проверяет – по суточному кэшу, с `--force` спрашивает репо сразу. Скилл вызывает `--check` перед каждым открытием редактора и при новой версии сначала предлагает обновиться.

Релиз: поднять `__version__` в `revizor.py`, раздел в `CHANGELOG.md` с тем же номером (это проверяет тест), тег `vX.Y.Z`.

## Стилевые пары

Файлы правок остаются в папке документа. Правки `kind: "edit"` – готовые пары «было → стало» с причиной и форматом текста. Их можно собирать отдельным инструментом в примеры для своего скилла стиля. У автора это делает личная синхронизация, в репо её нет.
